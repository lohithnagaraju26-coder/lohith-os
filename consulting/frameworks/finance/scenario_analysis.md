# Scenario Analysis

## Category
Finance / Strategy / Decision Analysis

## Purpose
Evaluate how a business decision performs under different plausible future conditions rather than relying on a single forecast.

## Core Question
How attractive is the decision under different plausible scenarios, and which assumptions drive the difference?

## Use When
- A decision depends on uncertain future conditions.
- Management needs to compare best-case, base-case, and downside outcomes.
- Market entry or investment economics depend on uncertain assumptions.
- External factors could materially change expected results.
- A single forecast could create false confidence.
- Management needs to understand strategic resilience under uncertainty.

## Do NOT Use When
- There is no meaningful uncertainty affecting the decision.
- The scenarios are arbitrary and unsupported.
- The objective requires precise forecasting rather than strategic uncertainty analysis.
- The decision is entirely deterministic.
- Scenarios differ only cosmetically and do not change decision implications.

## Key Questions
- What uncertainties could materially affect the outcome?
- What are the key assumptions?
- Which assumptions are relatively certain?
- Which assumptions are highly uncertain?
- What are the most plausible scenarios?
- What defines the base case?
- What defines the upside case?
- What defines the downside case?
- How does the decision perform in each scenario?
- Which assumptions cause the largest differences?
- Does the recommendation change across scenarios?
- What early signals would indicate which scenario is emerging?
- Can the organization adapt if the downside scenario occurs?

- Timing assumptions
- Scenario definitions
- Expected probabilities where appropriate

## Analysis Process
1. Define the decision being evaluated.
2. Identify assumptions that materially influence the outcome.
3. Separate controllable variables from external uncertainties.
4. Identify the most important uncertainties.
5. Construct a small number of plausible scenarios.
6. Define the assumptions for each scenario.
7. Calculate business outcomes under each scenario.
8. Compare financial and strategic implications.
9. Identify assumptions that change the recommendation.
10. Identify leading indicators that reveal which scenario is emerging.
11. Define contingency actions where useful.
12. Determine whether the decision remains attractive across plausible scenarios.

## Expected Output
- Defined scenarios.
- Assumptions for each scenario.
- Business outcomes under each scenario.
- Key drivers of divergence.
- Scenario-sensitive recommendation.
- Monitoring indicators.
- Contingency actions where appropriate.

## Interpretation
Scenario analysis should reveal how robust the decision is. A strong decision may remain attractive across multiple plausible scenarios. A fragile decision may depend heavily on a small number of uncertain assumptions.

## Limitations
- Scenarios are not predictions.
- Poor assumptions produce misleading scenarios.
- Too many scenarios create unnecessary complexity.
- Probabilities can create false precision.
- Scenarios can miss unexpected discontinuities.

## Common Mistakes
- Creating only optimistic and pessimistic extremes.
- Choosing arbitrary assumptions.
- Treating scenarios as forecasts.
- Building too many scenarios.
- Ignoring interactions between assumptions.
- Failing to connect scenarios to decisions.
- Failing to define indicators that reveal which scenario is emerging.

## Consulting Judgment
Use scenario analysis to test the robustness of a decision rather than to create elaborate forecasts. Focus on the few uncertainties that could actually change the decision.

## Framework Reasoning Rule
Build scenarios around decision-changing uncertainties, not around arbitrary variations in every assumption.

## Framework Combination Rules
- Use PESTEL to identify external uncertainties.
- Use Sensitivity Analysis to identify which numerical variables have the greatest impact.
- Use Decision Matrix when multiple strategic alternatives must be compared.
- Use Break-Even Analysis to determine the minimum conditions for viability.
- Use Risk Analysis when downside exposure is material.

## Framework Selection Hierarchy
1. Identify uncertainties that can change the decision.
2. Build a small number of plausible scenarios.
3. Quantify their consequences where possible.
4. Test whether the recommendation changes.
5. Define monitoring indicators and contingency actions.
