# LOHITH OS — CONSULTING FRAMEWORK LIBRARY

## Purpose

This library defines the analytical frameworks available to LOHITH OS.

Frameworks are tools, not answers.

LOHITH OS must first understand:

1. The business situation
2. The objective
3. The decision
4. The problem type
5. The key questions
6. The evidence required

Only then should it select frameworks.

---

# 1. STRATEGY FRAMEWORKS

## 1.1 SWOT Analysis

### Purpose

Assess internal strengths and weaknesses alongside external opportunities and threats.

### Best Used For

- Strategic diagnosis
- Business reviews
- Competitive positioning
- Identifying strategic options

### Core Questions

- What are we good at?
- Where are we weak?
- What external opportunities exist?
- What external threats exist?

### Inputs

- Internal capabilities
- Performance data
- Market information
- Competitive information

### Outputs

- Strengths
- Weaknesses
- Opportunities
- Threats
- Strategic implications

### Warning

SWOT should not be used as a generic brainstorming exercise.

It should lead to strategic implications.

# 14. ISSUE TREE

## Purpose

Break a large problem into smaller, logically structured questions.

### Example

Problem:

"Profit is declining."

Break into:

Profit

├── Revenue

│   ├── Price

│   └── Volume

│       ├── Customers

│       └── Transactions

└── Costs

    ├── Fixed Costs

    └── Variable Costs

### Core Principle

A good issue tree should help answer:

"What must be true for us to understand the problem?"

# 20. FRAMEWORK SELECTION RULES

LOHITH OS must follow these rules:

### Rule 1

Never select a framework simply because it is famous.

### Rule 2

Select frameworks based on the business question.

### Rule 3

Use multiple frameworks when the problem requires multiple perspectives.

### Rule 4

Do not use frameworks that do not add analytical value.

### Rule 5

Frameworks should produce actionable insight.

### Rule 6

Evidence should be stronger than assumptions.

### Rule 7

Frameworks should support decision-making rather than replace judgment.

### Rule 8

If a framework produces an answer that conflicts with strong evidence, investigate the conflict.

### Rule 9

Framework selection can change as new evidence appears.

### Rule 10

The final recommendation should not simply be a framework output.

It must integrate:

Evidence

+

Analysis

+

Business context

+

Trade-offs

+

Risk

+

Execution feasibility

# 22. FRAMEWORK FIT CRITERIA

A framework should be evaluated against:

## Relevance

Does it address the actual business question?

## Evidence Availability

Can the required information realistically be obtained?

## Analytical Value

Will it produce useful insight?

## Complexity

Is it appropriate for the problem?

## Decision Relevance

Will the result help management make a decision?

## Actionability

Can the resulting insight lead to action?

---

# 23. FRAMEWORK OVERUSE WARNING

LOHITH OS should avoid:

Framework dumping.

Framework dumping means presenting many frameworks without explaining:

- Why they were selected
- What question they answer
- What evidence they require
- What decision they support

A consultant should prefer:

One useful framework

over

Ten irrelevant frameworks.

---

# 24. CONSULTING QUALITY STANDARD

Every framework-driven analysis should attempt to answer:

1. What question are we answering?
2. Why does this question matter?
3. What evidence do we have?
4. What assumptions are we making?
5. What does the analysis show?
6. What does it mean?
7. What decision does it support?
8. What are the risks?
9. What should happen next?
