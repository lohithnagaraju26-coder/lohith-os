# Decision Matrix

## Category
Strategy / Decision Analysis

## Purpose
Compare multiple alternatives against explicit decision criteria so a complex decision can be evaluated systematically and transparently.

## Core Question
Which alternative provides the strongest overall value when the relevant strategic, financial, operational, and risk criteria are considered?

## Use When
- Multiple alternatives must be compared.
- A decision involves several qualitative and quantitative criteria.
- Different stakeholders value different criteria.
- Management needs to make trade-offs explicit.
- Market entry options, vendors, products, or strategic initiatives must be ranked.
- A structured decision is preferable to intuition alone.

## Do NOT Use When
- There is only one realistic alternative.
- The decision depends on a single dominant variable.
- Criteria cannot be defined meaningfully.
- Scores would be arbitrary and unsupported.
- The decision requires detailed causal analysis before alternatives can be compared.

## Key Questions
- What alternatives are being compared?
- What criteria matter to the decision?
- Which criteria are must-have constraints?
- Which criteria differentiate the alternatives?
- How important is each criterion?
- What evidence supports each score?
- Are criteria overlapping?
- Are some criteria double-counting the same underlying factor?
- Which alternative performs best overall?
- Which alternative performs best on critical criteria?
- How sensitive is the ranking to different weights?
- What risks could overturn the ranking?
- Which assumptions are most important?
- Is there a clear winner or should the decision remain conditional?

## Required Inputs
- Alternatives
- Decision objective
- Evaluation criteria
- Criteria definitions
- Criteria weights where appropriate
- Evidence for each alternative
- Minimum thresholds
- Risk information
- Cost information
- Strategic requirements

## Analysis Process
1. Define the decision objective.
2. List realistic alternatives.
3. Define the criteria that matter to the objective.
4. Separate must-have constraints from scored criteria.
5. Remove overlapping or redundant criteria.
6. Assign weights where relative importance differs.
7. Evaluate each alternative against each criterion.
8. Record the evidence supporting each score.
9. Calculate overall results where appropriate.
10. Test the ranking against reasonable changes in weights or assumptions.
11. Identify risks and disqualifying factors.
12. Determine whether the result is robust or conditional.
13. Recommend the best option or identify what additional evidence is required.

## Expected Output
- Structured comparison of alternatives.
- Criteria and weights.
- Evidence-backed scores.
- Overall ranking or recommendation.
- Sensitivity of the ranking.
- Key trade-offs.
- Conditions that could change the decision.

## Interpretation
A decision matrix is useful when it makes trade-offs explicit and evidence visible. The numerical score is a decision aid, not an objective truth. A slightly higher score should not override a critical disqualifying risk.

## Limitations
- Scores can contain subjective judgment.
- Weights can materially affect the result.
- Poor criteria produce misleading rankings.
- Numerical scoring can create false precision.
- Interactions between criteria may be missed.
- Critical risks can be hidden by a high average score.

## Common Mistakes
- Choosing criteria to favor a preferred alternative.
- Using too many criteria.
- Double-counting related criteria.
- Assigning arbitrary weights.
- Scoring without evidence.
- Ignoring minimum requirements.
- Treating the final score as definitive.
- Failing to test sensitivity to weights.
- Allowing a severe risk to disappear inside an average score.

## Decision Impact
High

## Consulting Judgment
Use the decision matrix after the decision criteria and alternatives are understood. Keep the criteria tied directly to the decision objective and use evidence rather than intuition wherever possible.

## Framework Reasoning Rule
Make trade-offs explicit without allowing arbitrary scoring to replace business judgment.

## Framework Chain
Decision Objective
→ Alternatives
→ Criteria
→ Evidence
→ Weighting
→ Scoring
→ Sensitivity
→ Risk Check
→ Recommendation

## Framework Combination Rules
- Use PESTEL to inform external-environment criteria.
- Use Scenario Analysis to test how alternatives perform under different conditions.
- Use Sensitivity Analysis to test whether weights or assumptions change the ranking.
- Use Build vs Buy when technology implementation alternatives are being compared.
- Use Risk Analysis to identify risks that should act as hard constraints rather than ordinary scores.

## Framework Selection Hierarchy
1. Define the decision objective.
2. Identify realistic alternatives.
3. Establish must-have constraints.
4. Define a small set of meaningful criteria.
5. Support scores with evidence.
6. Test ranking sensitivity.
7. Override the matrix when critical risks or strategic constraints require it.
